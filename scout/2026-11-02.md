## [search] corr-integral: let the correction tables learn the whole gap, not half of it

**What happens now (src/search.rs, `update_correction` and the node
code around line 642).** Each table entry is moved toward
`best_score - static_eval`, where `static_eval` is the eval *already
corrected* by the same tables. So the tables chase the part of the gap
they have not yet explained, and an entry is averaged toward that
leftover, not increased by it. When the correction is right the leftover
is 0, so the entry decays toward 0 again. The balance point is short of
the true gap g:

- one table (before nonpawn-corr2): entry = g - entry, correction = g/2;
- today (pawn + mean of the two non-pawn tables, all equal at balance):
  correction = 2g/3;
- corr-avg (the average of those): correction = g/2 again.

That lines up with the record: g/2 -> 2g/3 was nonpawn-corr2's +3.6
(with the extra detail), and 2g/3 -> g/2 was corr-avg's -6.6. On this
reading the "unsure" share is a side effect; the steady under-correction
is the main lever, and it is still a third of the gap today.

**Change.** Make the update additive (a running sum of leftovers):
`entry += leftover * weight / CORR_WEIGHT_SCALE`, clamped as now. With
any mix of tables the balance point becomes correction = g (leftover 0).
Outside-chess source: control theory: a controller that only reacts to
the current error ("proportional") always stops short of the target;
adding the running sum of the error ("integral") removes that gap.
Equivalently, it is the least-mean-squares filter rule from signal
processing (each table takes its share of one shared error). Stability:
the combined step is at most 2 x 16/256 = 1/8 of the leftover per update,
far below the unstable limit.

**Cheap test.** Two variants, same base, [0, 5]:
1. corr-integral: the additive update only.
2. corr-integral-u18: the same plus the unsure threshold 12 -> 18, so
   about the same share of nodes stays "unsure" as now (the correction
   grows about 1.5x). This separates the two causes corr-avg could not.
If 1 passes and 2 does not, the extra unsure nodes matter; if both
pass, it is the size of the correction.
Before games, a one-minute check: log the mean |correction| on the bench
for main and the variant; expect about 1.5x.

**Prediction.** Self-play -3 to +8, about 35% to pass [0, 5]. Kept against
rated engines: about 50% (eval-quality changes held up in calibration
better than pruning ones, but this is unproven for corrections).

**Risk.** The leftover comes from shallow searches and is noisy; shrinking
toward 0 (today's behaviour) may be acting as a useful brake on noise, so
the full gap could overshoot and lose. If corr-integral fails, a halfway
point (keep the averaging but correct with 1.5x the sum) is the fallback,
not more tables.
