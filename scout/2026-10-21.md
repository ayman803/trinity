## [search] Idea: split #38 into its two halves and test each, then push the half that worked

**What it is.** #38 did two things at once (its commit says so): (a) score
quiet moves only when the picker first reaches them, and (b) once a quiet
move is pruned, drop the remaining quiets. (a) is close to pure speed:
it should search the same tree faster. (b) changes the tree: when one
quiet is pruned, later quiets that would have survived the pruning test
on their own (for example a quiet move that gives check, or one with a
different history score) are now skipped too. That is a stronger pruning
rule, and it is the more likely source of most of the +21.5, since the
pure speed part is worth about +3 by the time-odds ruler and the
"fresher ordering" follow-up (#41) failed.

Test the two halves separately against the old main (before #38): one
branch with (a) only, one with (b) only. Whichever half carries the gain
says where the next candidates are:
- if (b): the gain came from pruning more of the late quiet moves, so the
  next candidates are the thresholds of that pruning (the move count where
  it starts, and which moves are exempt), tuned with the runner tuner or
  by SPRT;
- if (a): the speed lane is worth more than the time-odds ruler says, and
  the profile should be re-read for similar "work done for moves never
  searched".

**Why it might work.** A 2x2 factorial design (Fisher, agricultural and
industrial experiments): when one change bundles two factors and wins big,
measuring each factor alone tells which one to develop further; a single
combined result cannot. It also guards the result at slower clocks:
pruning gains (b) are the kind that can shrink with more time, which the
40/60 nights already showed for the time-management gains.

**Cheap test.** Two GitHub tests of about 4000 games each against the old
main (two branches carved from the #38 commit), no PC time. Predictions
to write first: (a) alone +2 to +5; (b) alone +12 to +20.

**Prediction.** 0 Elo directly. It decides tomorrow's candidates; if (b)
carries the gain, a tuned version of its threshold is worth about +2 to
+6 self-play, kept against rated engines about 50% (pruning gains shrink
with time). Value as a tool: it stops the search lane from guessing at
#38's cause with follow-ups like #40 and #41.

**Risk.** About 8000 GitHub games (half a slot-day). If both halves show
about half the gain each, the result is less useful, though it still
rules out a single cause.
