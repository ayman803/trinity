## [search] corr-cap: check whether the 32 cp cap is what held corr-integral back

**What.** Each correction entry is clamped to +/- 32 cp (CORR_MAX). The
Session measured corr-integral's mean correction at 1.16x main's, not the
1.5x the balance-point argument predicts, and named the cap as a likely
reason. If many entries sit at the cap, corr-integral could not grow the
correction, so its result so far (+0.6 GitHub, +1.3 PC, both undecided)
says little about the idea itself.

**Cheap test (CPU minutes, no games).** On the 60 game positions used for
speed checks, after searching each, count the share of touched entries
at +/- 32 cp, for main and for corr-integral. Decision fixed now: if more
than 5% of corr-integral's touched entries sit at the cap, test
corr-integral with the cap at 64 cp ([0, 5]); if under 1%, the cap is
not the reason and corr-integral's result stands as it lands.

**Prediction.** For the cap-64 variant if it is run: self-play -4 to +5,
about 15% to pass. Kept against rated engines: about 50%.

**Risk.** A bigger cap lets one noisy shallow result move the eval
further; the cap may be doing useful work. The diagnostic costs minutes
and decides whether a test is worth having at all.

## [network] Sibling-ranking check: score a network on how it orders the moves of one position

**What.** Today's offline gate is held-out loss: how well the network
predicts game results. The search does not use that. It uses the network
to compare the positions after each legal move of the same position.
A network can predict results equally well and still order sibling
moves better or worse. On 1 November long900 tied Control2 on loss
(0.015%), yet leads +4.9 +/- 3.9 after 9400 games; Control2 itself was
0.25% better than main on loss and scored -0.2. Loss is not ranking
the networks the way games do.

**Measure.** For 2000 held-out positions: play each legal move, score
the result with the network plus a quiescence search, and compare that
order with the order from main's depth-12 search of the same moves
(rank agreement: top-1 match and Kendall's tau, standard measures in
information retrieval for "does this ranking agree with that one").
Main's depth-12 search uses main's network, so it slightly favours
main; use the 2048 network's or a referee-free deep search at depth 14
as a second reference if the numbers are close.

**Cheap test.** Score every network with a known game result: main,
Control2, long900, Seed2, wide2048 (-29.8, but mostly speed), drill
(-92). If the ranking measure orders them as the games did, where loss
did not, adopt it as the network gate beside loss. Cost: CPU only,
about an hour on the PC (a short job, fits rule 17's daytime slot).

**Prediction.** No Elo directly. Value: fewer full SPRTs on networks
that will not pass (each network SPRT costs about a day of GitHub time).
I put the chance that it ranks the known networks better than loss at
about 40%.

**Risk.** Six networks is a small sample; agreement could look good by
chance. Depth-12 orders are themselves noisy at the bottom of the list;
weight the top 3 moves most (that is where the search spends its time).
