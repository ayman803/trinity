# Scout, 8 November 2026

No new test candidate today. Instead, measurements that bear on how the
network lane judges networks (sections B to D) and one search
measurement (A). Everything was done in the cloud on Trinity's own code,
networks and held-out positions; no other engine's material was read.

## A. [search] Singular extension: measured, not proposed

Without the whole singular-extension block (the half-depth check of the
hash move, its +1 extension, multi-cut and the negative extension) the
bench needs 581057 nodes to depth 10 instead of 982007: 41% fewer, more
than the check extension's 36%. no-checkext is at -5.0 +/- 4.6 after 6000
games, so at this engine's speed an extension that costs a third of the
nodes still pays for itself; the singular block costs more and does the
same kind of work. Expected to lose; not proposed. It is the last
first-commit rule never tested alone, so the removal campaign ends here
unless the Session wants the formal test for the record.

## B. [network] Where the held-out loss comes from

Main's network on all 150,000 held-out positions (result loss, the same
formula as the Session's: overall 0.08179 against the logged 0.081781).

| Positions by | share | loss | relative |
|---|---|---|---|
| move 1-15 | 12% | 0.129 | 1.58 |
| move 16-30 | 26% | 0.119 | 1.46 |
| move 31-50 | 28% | 0.083 | 1.01 |
| move 51-80 | 22% | 0.044 | 0.54 |
| move 81+ | 12% | 0.020 | 0.25 |
| 25-32 pieces | 25% | 0.132 | 1.62 |
| 17-24 pieces | 29% | 0.104 | 1.27 |
| 11-16 pieces | 22% | 0.060 | 0.73 |
| 2-10 pieces | 24% | 0.012-0.031 | 0.15-0.38 |

Positions up to move 30 are 38% of the set and carry 56% of the loss.
That loss is mostly the game's own uncertainty (the result is 40 moves
away), not the network's error: the metric measures how predictable the
result is from here, and every network faces the same unpredictability.

## C. [network] Eight tested networks on the same positions: no slice of the result loss orders them like the games

Engines built from the eight network branches with a game result
against main (same speed class; the 2048 net left out), all scored on
the 150,000 positions.

| network | Elo vs main (games) | loss, all | loss, move > 30 | loss, pieces <= 16 | confident and wrong (%) |
|---|---|---|---|---|---|
| main | 0 | 0.08179 | 0.05693 | 0.04098 | 6.48 |
| long900 | +7.0 | 0.08157 | 0.05662 | 0.04079 | 6.52 |
| Seed2 (kb16) | +1.2 | 0.08160 | 0.05664 | 0.04075 | 6.56 |
| avg 550-600 | +0.4 | 0.08178 | 0.05689 | 0.04094 | 6.47 |
| Control2 | -0.2 | 0.08159 | 0.05669 | 0.04088 | 6.53 |
| avg 450-600 | -1.3 | 0.08177 | 0.05688 | 0.04098 | 6.51 |
| kb16 | -2.1 | 0.08158 | 0.05663 | 0.04065 | 6.44 |
| control | -9.7 | 0.08166 | 0.05661 | 0.04085 | 6.44 |
| new-data | -10.9 | 0.08145 | 0.05654 | 0.04092 | 6.80 |

The sharpest result-based comparison possible, pairing each network with
main only on the positions where the two disagree by more than 60 cp
(43,000-48,000 positions each; standard error about 0.0002): every
network predicts results better than main there, and the order is
new-data (-10.9 Elo) best at -0.00096, then Control2 -0.00068, long900
-0.00069, kb16 -0.00063, Seed2 -0.00057, control -0.00042. The network
that plays worst predicts results best; the one that plays best is in the
middle. These networks differ from main by a median 35 cp, by more than
60 cp in about 30% of positions, and are all within 10 Elo of it: the
search is indifferent to eval offsets of that size, and whatever makes
one network play better than another is not visible in how well it
predicts game results, at any slice I tried (overall, by phase, by
material, confident positions, disagreements).

Reading: a result-loss gate cannot pass or rank same-speed recipe
variants; it can only catch a broken run (a loss far worse than main's).
The "0 to 0.3% better" band is below the metric's power for these
networks, old held-out set or new.

## D. [network] Move-ranking metric (idea of 3 November), first measurement

A first version using the raw static eval of each child (no quiescence)
was uninformative: for every network the static best child is the
search's best move in only about 15% of 496 positions (the static best
is usually a capture the search refutes; mean gap 340 cp), so all eight
networks scored alike. The second version resolves each child with a
depth-1 search (the network's eval after quiescence) against main's
depth-7 search of the same children; its result is appended below when
the run finishes (a follow-up commit today).
