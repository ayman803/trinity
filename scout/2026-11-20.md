## [network] moredata-600: the data lever, redesigned for the new recipe

**What.** WDL 0.25, 600 superbatches, seed 20261019, on the 5.65 billion
positions of the 17 October more-data run (its second-1 and second-2
.data files, if still on the PC, next to big-1..4). Partner: wdl25 (600),
same seed and length. One change: the data. About 5 hours, one night.

**Why now.** The more-data run of 17 October lost -10.85 at WDL 0.5. At
WDL 0.5 the number of passes over the data mattered (+5.65 and +4.81 for
1.5x the passes, two seeds), and that run had fewer of them (10.7 instead
of 16.4), so its loss could have been the passes, not the data. At WDL
0.25 passes no longer matter (900 vs 600 superbatches: -1.0 +/- 3.9, SPRT
#133). So the cost that sank the old run should be gone, and what is left
is the benefit it was meant to test: 55% more distinct positions, against
the memorisation the 2048 run showed (training positions 2.5% better,
held-out 1.3%). This replaces the equal-passes design of 7 November (1390
superbatches, 11.6 hours) with a 5-hour run.

**Needs.** kb16.ps1 able to take the more-data files (ESTIMATES.md
already notes this for equal-passes), so one approval; and a check that
the second-file .data parts still exist (the newdata script kept them and
deleted only its raw parts; disk was about 181 GB with them).

**Test.** Scale check in the cloud first (as for wdl25 and wdl0), then
the 400-game screen and the head-to-head against wdl25 x1.2, [0, 5].

**Prediction.** Self-play -4 to +6, about 25% to pass. Kept against rated
engines: about 50%.

**Risk.** If the files were deleted, re-making them costs a download and
about an hour of CPU. If it fails, the data lever is closed at this
network size and the remaining network questions are structural (size,
buckets), which have a speed cost.
